# 60秒版の設計と検収（2026-10-19）

対象: 30秒・16小節の「Deep Field / 005」版を、60秒・32小節の新曲版にする。設計はClaude Opus 5.5、実装はGPT-6.1 Sol（xhigh）。データ（79件・観測 2023-01-01〜2026-10-19）は変更しない。

依頼: 尺を1分にする。BGMを派手にする。アニメーションの調整は任意。

## 1. 尺と構成

128 BPMを維持する（1小節 = 1.875秒）。32小節がちょうど60.000秒になり、30fpsで1800フレーム。

| 3–10 | 3.75–18.75 | グラフ（暦の進行） | 2023-01-01 → 2024-04-07 | A「Ignition」 |
| 11–14 | 18.75–26.25 | 同上 | → 2024-11-24 | lift「Liftoff」 |
| 15–22 | 26.25–41.25 | 同上 | → 2026-03-02 | drop1「Ignite」 |

- 内訳: intro 2小節、travel 24小節、hold 2小節、outro 4小節。`makeTimeline` の既定値をこの値にする。
- 暦は一定速度のまま（約57.8日／小節、30秒版の半分の速さ）。名前・名札が読みやすくなる。
- この配分は実データの密度に合わせている。drop1の頭（2024-11-24）の直後に2024年12月の集中（o1・Llama 3.3・Gemini 2.0 Flash・DeepSeek V3）が来る。buildの4小節に2026年3月以降の約30件が入り、breathの半小節にも最後の集中（9/22〜10/17の7件）が鳴る。発表の打音で緊張が高まり、観測終了日でdropする。
- 区間の小節数の一般則（`--duration` の圧縮版や別データ用）: travelの小節数Tに対し A = round(T/3)、lift = round(T/6)、drop1 = round(T/3)、build = 残り（最低2小節）。T=24で 8 / 4 / 8 / 4 になる。Tが小さく区間が作れないときは、短い区間から省いて例外を出さないこと。
- `cuePoints` に `lift`・`drop1`・`finale`（最後の小節の頭）を追加する。既定の時刻は intro 3.75、lift 18.75、drop1 26.25、build 41.25、gap 46.875、breath 47.8125、drop 48.75、outro 52.5、finale 58.125。すべて小節線上（breathだけ半小節）。

## 2. BGM（新曲「Supernova / 006」）

方向: 128 BPM・G短調のフェスティバル系プログレッシブハウス。005の暗いダブ寄りの質感から、明るく厚いスーパーソウ・リフ・フック・大きなドロップへ寄せる。合成方式は従来どおり（発振器とシード付きノイズのみ、録音素材・外部楽曲・生成サービス不使用、決定的）。`SCORE.title` を `Supernova / 006` にする。旧曲は「Deep Field / 005」として docs/audio.md の履歴に残す。

### 和声

- 進行は1小節1和音で Gm – E♭ – B♭ – F(sus2)（i–VI–III–VII）。buildは E♭ – E♭ – F – F でdropのGmへ上がる。
- 発表のチャイムはG短調ペンタトニック（G・B♭・C・D・F）。和音にA・E・F♯・B・C♯を入れない（チャイムの半音下の音を避ける既存の規則を維持）。Fは sus2（F・G・C）で鳴らす。
- 推奨ボイシング（MIDI）: Gm = 55 62 67 70 74、E♭ = 51 63 67 70 74、B♭ = 58 62 65 72、Fsus2 = 53 60 65 67 72。発表がある区間（drop1まで）は和音の最高音をD5（74）以下に置き、チャイム帯（MIDI 79–89、784–1397 Hz）を空ける。
- サブの根音は40–90 Hzに収める（例: G1・E♭2・B♭1・F1またはF2）。

### 新しく入れる音

| 音 | 内容 | 主に鳴る区間 |
| --- | --- | --- |
| スーパーソウ和音 | 1音あたり7声、±20〜25セントのデチューン、ステレオに広げる（低域150 Hz以下はモノラル）。キックでサイドチェーン（深め）。帯域制限された既存の `saw()` を使う | intro（フィルターで閉じた膨らみ）、lift（持続音でフィルターが開く）、drop1・drop（裏拍8分のリズムで刻む） |

| ローリングベース | 裏拍8分のノコギリ波ベース＋サブ。キックでポンプ | drop1・drop |
| フック（リード） | スーパーソウのリード＋1オクターブ上の重ね。下記の4小節フック | drop（発表がすべて終わった後）だけ。drop1では和音のリズムがフックの役になり、発表のチャイムが旋律になる |

- 1小節目（Gm）: [0,74,3] [3,70,3] [6,67,2] [8,70,2] [10,74,3] [13,77,3]
- 2小節目（E♭）: [0,79,3] [3,77,3] [6,74,2] [8,70,2] [10,74,6]
- 3小節目（B♭）: [0,74,3] [3,70,3] [6,67,2] [8,70,2] [10,74,3] [13,72,3]

同じ3-3-2のリズムをdrop1のスーパーソウ和音の刻みに使い、dropで旋律として初めて現れる構成にする。

### 区間ごとの編曲

- **intro（1–2）**: 0秒にインパクト＋サブブーム、閉じたGmのスーパーソウが膨らむ。2小節目はキックを2分音符で、ノイズライザー、最後の拍に16分のスネアフィル。
- **A（3–10）**: 4つ打ち、ポンプするサブ＋ベース、裏拍クローズドハット。7小節目からクラップ、アルペジオが16分に、ハットが増える。3・7小節目にクラッシュ。スーパーソウ和音は閉じたフィルターで裏拍に軽く。
- **lift（11–14）**: 和音が持続音になりフィルターが開く。4小節のノイズライザー。13–14小節でスネアロール。14小節の3・4拍はキックを抜き、リバースシンバルでdrop1へ。
- **drop1（15–22）**: インパクト＋クラッシュ＋サブブーム。3-3-2で刻むスーパーソウ和音、ローリングベース、全ドラム。19小節目にクラッシュ、18・22小節の最後の拍にフィル。
- **build（23–26）**: 23–24はキック＋8分スネア、ベースはハイパスで細く、和音は持続して上がるフィルター、ライザー。25は16分スネア。26前半は既存どおり8分のキックロール、26後半（breath）はキックとベースを抜き、スウェルとライザーだけ。最後の発表の集中がここで鳴る。
- **drop（27–30）**: 曲で一番大きい区間。インパクト、クラッシュ、サブドロップ、フック（2オクターブ重ね）、全ドラム。まとめ画面に入っても続く。
- **outro（31–32）**: 31小節はハイパスを上げながら続け、32小節の頭でGmの最後の一撃（スーパーソウ和音＋インパクト＋クラッシュ）。残響で減衰し、60.0秒で無音にする（最後の約1秒で確実にゼロへ）。フェードアウトではなく、一撃で終わる構成。

### ミックスとマスタリング

- 目標 −14 LUFS（統合）、True Peak −1.0 dBTP以下。`SCORE.targetLufs` / `truePeakDb` を更新する。マスタリングは従来どおり線形のゲインのみ（`audio-master.mjs` の仕組みを維持）。届かない場合は合成側のリミッター・サチュレーションで波高率を整える。
- 発表の音は維持する（上昇音、破裂、会社別の音程と定位のチャイム、パチパチ、近接時のゲイン共有、発表日に厳密に一致、拍へ寄せない）。BGMが厚くなる分、発表の周りのダッキング（スーパーソウ・アルペジオ・ハット・リードを深めに）とSFXのゲインで聞こえを保つ。キックとサブは発表でダックしない。
- 区間の音量の目安（BGMステム、小節RMS）: drop ≥ drop1 + 0.5 dB、drop1 ≥ Aの最大 + 3 dB、build 1小節目 ≤ drop1 − 2 dB、breath ≤ drop − 10 dB。

## 3. 映像

本日の判断（カメラの拍・小節・発表ごとの拡大、周期的な引き、揺れをすべて外した）を維持する。カメラは時刻だけで決まる1本の追従ショットのまま、拍への反応は位置・倍率ではなく光だけで表現する。「1つの開花＝1件の発表」も維持し、架空の花火・粒子数や半径の時期による差は加えない。

### 時間の調整

- カメラ: 暦が半分の速さになるので、追従のガウス窓（現在0.9秒）など時間の定数を「暦の日数あたり同じ動き」になるよう換算し、必要なら調整する。寄りの段階は intro→build（ゆっくり）、build→breath、breath→drop の3段を新しいcue pointに合わせ直す。dropでの全体への引き（0.7秒）は維持。
- 名札 `TAG.life` は1.2→1.6秒。`merge`・`rows` は維持。
- 花火の `FIREWORK.rise`（0.36秒）・`life`（1.9秒）・粒子数は維持（音との同期のため）。

### 新しい演出

1. **区間のエネルギー**: 曲の区間から `energy(t)`（intro 0.2、A 0.35、lift 0.5→0.7、drop1 1.0、build 0.6→0.9、breath 0.4、drop 1.0、outro 0.6）を作り、音と映像の両方が同じ区間定義を参照する（`timeline.mjs` などの共有モジュールに置く）。背景の星雲の強さ・星のきらめき・5社の色のごく薄い色の揺らぎ（drop1・dropだけ、会社色をゆっくり巡回）に使う。
2. **キックの光**: drop1・dropの間だけ、キックに合わせて背景の光と「今」を示す縦線・グラフ下端の線が短く明るくなる（0.12秒程度で減衰）。位置・倍率は動かさない。
3. **区間頭のショックウェーブ**: drop1とdropの頭で、会社色のグラデーションの細い光の帯がグラフと発表ペースのパネルを左から右へ1拍で横切り、枠と軸線が金色に光って1拍で戻る。liftの頭は弱めに。
4. **buildの緊張**: 「今」の縦線のグローが段階的に強くなり、画面の四隅が少しずつ暗くなる（最大25%程度）。breathの半小節は進行中の花火以外を約20%暗くし、dropで解放する。
5. **年表示**: 年が変わるとき、数字がオドメーターのように上へ入れ替わる（0.3秒）。既存の金色の変化も維持。
6. **再点火スイープ（27–28小節）**: 全体へ引いた後、drop + 1拍から縦の光の線が暦を左から右へ横切り（28小節の3拍目で終わる）、通過した発表のマーカーが会社色の光輪で順に光る（約0.4秒で減衰）。通過後の階段線と発表ペースの線を少し明るく残す。新しい花火は描かない。
7. **まとめ（29–31小節）**: 拍に合わせて入る。29小節1拍目に見出し、2拍目から日数／件の数字が1小節かけて数え上がる、年別の棒は1拍ずつずらして伸びる、30小節でECI 126→167を数え上げる、31小節で注記。
8. **エンドカード（32小節）**: 最後の一撃と同時に「EDIT THE DATA. REPLAY THE SKY.」とリポジトリ名を両形式で出す（横長は既存の要素と重ならない位置に）。金色のやわらかい光を1回、白い全画面フラッシュは使わない。59.0〜60.0秒で背景色へフェード。
9. **タイトル（1–2小節）**: 既存の文言と配置のまま、各行の登場を拍に合わせる（「NEW MODELS.」0拍、「LESS QUIET.」2拍目、説明2行は1小節目の3・4拍、線と期間・件数は2小節目にライザーと同期）。最後の0.24秒で既存どおりグラフへ抜ける。

### 光の安全基準

光の演出は `npm run qa:visual` の輝度走査（30fps）で両形式とも次を満たすこと。最大平均輝度 ≤ 0.16（現状 0.124 / 0.117）、近白色画素の最大割合 ≤ 0.015、連続フレーム間の平均輝度の変化の最大値 ≤ 0.03。

## 4. 維持する制約

- データ・出典・ECI・集計は変更しない。
- 発表の開花と破裂音は公開日の時刻に厳密に一致し、拍に寄せない。
- カメラは時刻だけで決まる（キックでズームが跳ねない、揺れなし。既存テストのキック前後のズーム検査と `npm run qa:visual` の `maxZoomBumpAtKick` で確認）。
- 決定的な合成・描画（同じ入力で同じ出力）。
- 外部素材なし、MITのオリジナル。フォントは同梱のManropeのみ。
- 既存のレイアウト検査（文字のはみ出し、名札の背景板、配色・コントラスト）を通す。
- `--duration` での圧縮レンダリング（例: `--duration 3`）が例外なく動く。

## 5. 合格条件

1. 両形式のMP4が60.0秒（±1フレーム）、1800フレーム、音声が全長を覆う。
2. `npm run validate`、`npm test`、`npm run build -- --out preview`、両形式の `render` / `verify:media`、`verify:artifacts`、`npm run qa:visual`、`node scripts/analyze-audio.mjs --fast` がすべて成功。
3. 音: 統合 −14.0 ± 0.5 LUFS、True Peak ≤ −1.0 dBTP、クリップなし。発表の80 ms窓で500–10 kHzのSFX/BGM比の中央値 ≥ +3 dB、同帯域でSFX ≥ BGMの発表が80%以上。区間の音量の目安（2章）を満たす。
4. 映像: 光の安全基準（3章）、キックでカメラが動かない（4章の検査）、名札・一覧・まとめの文字がはみ出さない。
5. テスト更新: 32小節の時計とcue point、区間の順序（intro, A, lift, drop1, build, roll, breath, drop, outro）、dropが最大の小節、drop1がAより大きい、最後の一撃の後に無音、`energy(t)` が音と映像で同じ区間を返す。

### 設計の目安から調整した点と理由

- **再点火の開始**: drop+1拍（49.21875秒）から **drop+0.7秒（49.45秒）**へ。1拍後では0.7秒の引きの途中なので、「全体へ引いた後」を優先した。終了は指定どおり **51.5625秒（28小節の3拍目）**。花火を追加せず、既存マーカーの光輪だけで再点火する。
- **breathの暗転**: グラフ・ペース・一覧などの主領域を約20%暗くし、花火と名札をその後に描く。ヘッダー／フッターと名札の可読性を保ち、名札の背景板が花火より手前にある制約を優先した。全面を一律20%暗くする形とは異なる。
- **追従窓**: 0.9→1.8秒、重みの時間オフセット0.25→0.5秒（travel比から計算）。導入の寄り0.95秒、dropの引き0.7秒は維持した。
- **ミックスの係数**: 発表チャイムの基礎ゲインを0.55→0.75、テクスチャ約−15 dB／打楽器約−16 dBの発表時ダック。7声和音・ハットを計測を見て強め、BGMの2–10kHz比を−13.10 dBにした。音量目安を満たしつつ、発表音も全件がBGMを上回る。
- **まとめの数値表示**: 初年の大きな数字も小数1桁の40.6に揃えた（旧表示は整数41）。年別の既存集計と表示精度を一致させたもので、計算式やデータは同じ。
- **GIFと検査**: 60秒を15 MB以内にするため800px/8fps→640px/6fps。音の通常解析は外部の旧スケッチなしで完走する形にし、旧比較は`--compare`へ。高速解析と輝度QAは表示だけでなく基準超過時に失敗する。
