# BGMを「Long Exposure / 007」に差し替えた記録（2026-10-20）

対象: 60秒版（116モデル）のBGM。映像・データ・発表音の設計は変えず、曲だけを作り直す。設計・実装・計測は Claude Opus 5.5。

依頼: 「BGMが最後に一気に大きくなる演出があまり良くない。BGM自体を完全に一新してもよい。これまでの定義は一度忘れてよい。」

## 1. 何が問題だったか

旧曲「Supernova / 006」は、観測終了日（48.75秒）の最後のdropで、直前の小節より約11 LU大きくなっていた。コミット 18753f1 の `preview/frontier-landscape.mp4` と新しいMP4の、小節ごとのラウドネス（FFmpeg `ebur128` の momentary をエネルギー平均）:

| 小節 | 区間 | 006 | 007 |
| ---: | --- | ---: | ---: |
| 3–10 | A（暦の進行） | −17.3〜−15.5 | −16.1〜−14.0 |
| 15–22 | 最初のdrop / グルーヴ | −14.2〜−11.3 | −14.0〜−12.2 |
| 23–25 | build | −19.3〜−18.3 | −13.6〜−12.7 |
| 26 | roll・breath | −21.1 | −13.8 |
| 27–30 | 最後のdrop / 結論 | −12.0〜−10.3 | −13.1〜−12.4 |
| 31 | 終わりの小節 | −17.6 | −15.4 |
| 32 | 最後の和音 | −21.1 | −18.0 |

006 は build と breath で −21 LUFS まで下げてから −10.3 LUFS へ跳ね、最後の4小節が直前から急に大きくなっていた。LRA は 6.1 LU。

## 2. 新曲の方針

- 音量は1本のゆるやかな弧にする（`musicArc`）。暦の進行にあわせて上がり、グルーヴで頂点、最後の4小節はグルーヴと同じ高さ、終わりの2小節は下がるだけ。区間の境目で段差を作らず、すべて小節をまたぐ傾斜にする。
- 観測終了日の山場は、音量ではなく「主題が初めて歌われること」で作る。主題の前半は、A区間でエレクトリックピアノが1オクターブ下で予告しておく。
- breath は半小節だけキック・ハット・ベースを抜く。サブ・パッド・シーケンスは残し、無音に近い谷を作らない。
- 発表音（上昇音・破裂音・社ごとのチャイム・パチパチ音）は 006 のまま。チャイムの5音（G5・B♭5・C6・D6・F6）は変ロ長調のペンタトニックそのものなので、曲を変ロ長調にした。和音はチャイムの半音下（A・E・F♯・B・C♯）を使わず、発表のある間は D5 より上に置かない。

構成・音色・ミックスの詳細は [docs/audio.md](../audio.md) を正とする。

## 3. 合格条件と結果

自動の検査（`npm test` は 8 kHz、`node scripts/analyze-audio.mjs` は 48 kHz・公開時の時計で同じ条件を使う。定義は `scripts/analyze-audio.mjs` の `sectionDynamics` と `ARC`）。BGMの小節ごとのRMSで、どちらの曲も 48 kHz・公開時の時計・116モデルで測った:

| 条件 | 上限・下限 | 007 | 006 |
| --- | ---: | ---: | ---: |
| 小節から次の小節への最大の上昇（3小節目以降） | ≤ 2 dB | +1.51 | +14.32 |
| グルーヴの最小の小節 − 暦の最初の4小節の最大 | ≥ 1.5 dB | +2.05 | +8.25 |
| 最後のdropの最大 − グルーヴの最大 | ≤ 0.5 dB | −0.41 | +3.99 |
| buildの最後の小節から最後のdropへの段差 | ≤ 1.5 dB | +0.85 | +11.25 |
| breath が最後のdropの最小より小さい | ≥ 1 dB | 1.85 | 41.49 |
| 終わりの小節が前の小節より小さい（最小） | ≥ 1 dB | 2.15 | 1.38 |

006 は1・3・4行目の条件で不合格になり、007 はすべて合格。

発表音とBGMの関係（どちらも 48 kHz・公開時の時計・116モデル。上の4行は破裂の直後 80 ms の 500 Hz〜10 kHz）:

| 項目 | 007 | 006（同じ116モデル） |
| --- | ---: | ---: |
| 中央値 | +10.21 dB | +13.67 dB |
| p10 | +7.03 dB | +7.82 dB |
| 最小 | +2.31 dB（GPT-5.6 Luna、45.65秒） | +3.95 dB（GPT-4.1、30.79秒） |
| BGMを上回るモデル | 116/116 | 116/116 |

| 全体のSFX/BGM（広帯域） | −13.59 dB | −15.49 dB |

007 は暦の区間でもBGMが鳴っている分、破裂の瞬間の余裕は 006 より小さい。それでも全モデルが 2 dB 以上BGMを上回り、暦の区間での発表音の大きさは 006 とほぼ同じ。

最終MP4（`npm run verify:media`）: 横長・縦長とも −14.05 LUFS / −3.45 dBTP、1800フレームすべてデコードでき、寸法・長さ・データのハッシュも一致。ebur128 の LRA は 6.1 LU → 3.0 LU。

## 4. 検査の変更

- 区間の音量差の検査（drop1 が A より 3 dB 大きい、最後のdropが drop1 より大きい、breath が 10 dB 下がる）は、最後に大きくなる構成そのものを要求していたので、上の弧の検査に置き換えた。006 は新しい検査で不合格になる。
- 「発表音は主役ではなく層」の検査は、全体のSFX/BGM比（< −12 dB）から、発表のある暦の区間（3〜26小節）の比（< −10 dB）に変えた。全体の比は、発表のない最後のdropが大きいほど下がる。006 の全体の比（テストの 8 kHz で −13.94 dB）は最後の大きなdropに支えられていた。暦の区間に限ると、8 kHz で 006 は −10.99 dB、007 は −11.25 dB で、発表音の目立ち方はほぼ同じ。
- キックの検査は、新しいキックの型に合わせた（導入の2つの鼓動、breathまでの4つ打ち、breathは無し、最後のdropの4つ打ち、終わりの2小節は無し）。
- 和音の検査は、和音を名前つきの組（`CHORDS.Bb` など）にしたのに合わせ、主題が変ロ長調の音だけでできていることも確かめるようにした。

## 5. 確認したこと・残ること

- `npm test`（79件）、`npm run validate`、`node scripts/analyze-audio.mjs`、`npm run verify:media`（両形式）、`npm run verify:artifacts -- --out preview`、`npm run qa:visual` がすべて通った。
- スペクトログラム（`output/qa/audio-plots/spectrogram-007-*.png`）と音量の推移（`stems-loudness.svg`）で、暦の進行にあわせたフィルタの開き、最後のdropでの主題の倍音、終わりの2小節の減衰を確認した。
- 007 は 006 より暗い（BGMの 2〜10 kHz の割合 −19.2 dB、006 は −13.1 dB）。チャイムの帯域を空けるためで、明るさが足りないと感じる場合はハットとシーケンスのフィルタで調整できる。
- 以上は計測による確認。曲としての良し悪しは、yuu さんの試聴で判断してもらう。
