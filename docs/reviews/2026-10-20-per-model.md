# モデル単位の花火にする設計と検収（2026-10-20）

対象: 60秒版（「Supernova / 006」、79件）の選定単位を、「社・日付ごとの1件」から「名前の違うモデルごとの1発」に変える。設計はClaude Opus 5.5、実装はGPT-6.1 Sol（xhigh）。尺・曲・カメラ・区間の構成は変えない。

依頼: 映像で「Claude Opus 4」が抜けて見える。主要なモデルに抜けがあるかもしれない。まとめずに、それぞれのモデルの花火を打ち上げるべきか。

## 1. 何が問題か

- Opus 4 は 2025-05-22 の「Claude 4」として入っていたが、Opus 4 と Sonnet 4 を1件にまとめていたため、映像には「Claude 4」としか出ず、Sonnet 4 は高さも名前も出なかった。Claude 3（Opus・Sonnet）、GPT-5.6（Sol・Terra・Luna）、Llama 4（Maverick・Scout）、Muse Wonder（Wonder・Full）、GPT-6 Sol（Sol・Luna）も同じ。
- 小型の階層の扱いが社ごとにずれていた。Gemini の Flash は版番号を開くときだけ数える一方、o3-mini・o4-mini・GPT-4o mini・Haiku・Flash-Lite は数えなかった。Epoch の CSV には、5社で ECI があるのに未収録のモデルが79件ある（Claude Sonnet 4、Claude 3 Haiku、o1-mini、o3-mini、o4-mini、GPT-4o mini、Gemini 1.5 Flash、Gemini 2.5 Flash、Gemini 3 Flash、Claude Haiku 4.5 など。日付つきの更新や Gemma なども含む数）。

## 2. 選定ルール（第3版）

単位は「名前の違う汎用モデル1つ＝花火1発」。同じ社・同じ日でも名前が違えば別の発にする。

含める:
- 各社の主系統の汎用の言語・推論モデルで、新しい名前で公開されたもの。小さい・速い階層も含める（mini、nano、Haiku、Instant、Flash、Flash-Lite、Scout、Terra、Luna、V4 Flash など）。
- 公開プレビュー（試用・実験版を含む）は従来どおり含め、`stage: "preview"` にする。
- DeepSeek の主系統の改訂（V3-0324、R1-0528、V4 Pro 0813、V4.1 Flash-1017）は従来の規則のまま含める。

1発にまとめるもの:
- 名前がパラメータ数だけ違う版（LLaMA 7B〜65B、Llama 2/3/3.1/3.2/3.3 の各サイズ、DeepSeek LLM 7B/67B）は1モデルとし、ECI は最大のサイズを使う。

除外（従来どおり）:
- 同じ名前の更新・日付つきスナップショット・提供経路の追加（GPT-4o の更新、Gemini 2.5 Flash（May 2025）、DeepSeek V4 Flash 0731 など）。
- 計算量だけのモード（o1-pro、o3-pro、GPT-5 Pro 系、Deep Think、Speciale、Ultrafast）。
- 特化系（Codex、Coder、Math、Prover、VL、OCR、Vision-Exp、Muse Code）、画像・音声・動画、安全用（Llama Guard）。
- 他社モデルの蒸留や研究用の試作（R1-Distill、V2-Lite、MoE 16B）、端末内専用（Gemini Nano など）。
- 主に非公開モデルの社の補助のオープンウェイト系（gpt-oss、Gemma、Muse Spark Open）。
- 限定公開・未公開（Mythos、Fairwind、Behemoth、Gemini 3.5 Pro）。

日付は従来どおり公開元が示す初公開の暦日。発表だけで公開が後のもの（Claude 3 Haiku、Claude 3.5 Haiku、Gemini Ultra 1.0 など）は公開日を使う。

候補一覧は 7. に置く（調査は GPT-6.1 Sol、一次情報での裏取りは Claude）。

## 3. データ構造

- `data/releases.json` の1レコード＝1モデル。`schemaVersion` を 3 にする。フィールドは従来と同じ（`id, date, lab, name, stage, capability, sources, note`）。
- `name` は公式のモデル名（`Claude Opus 4`、`Claude Sonnet 4`、`GPT-4.1 mini`）。まとめ名（`Claude 4`）は使わない。
- `id` は `<lab>-<name の slug>` を基本にし、重複しないこと。
- 検証（`validateDataset`）: 「同じ社・同じ日は1件」の検査を、「同じ社・同じ日・同じ名前の重複禁止」に変える。日付順は従来どおり。
- 同じ社・同じ日のモデルの組を「発表」と呼ぶ。発表は保存せず、`launchGroups(data)`（新設、`src/data.mjs`）で導く: `{ id, lab, date, models }`。`models` は ECI の高い順、ECI なしはその後に JSON の順。

## 4. 打ち上げの時刻（連発）

- 発表の先頭のモデル（ECI が最も高いもの）は、従来どおり日付ちょうどに開く。
- 同じ発表の2つめ以降は、16分音符（`BAR_SECONDS / 16` = 0.1171875秒）ずつ遅れて開く。上昇の軌跡も同じだけずらす。x 座標は日付のまま、y 座標は各自の ECI のまま。暦では1発あたり約3.6日分の遅れになるが、位置は動かさない。
- 目的: 同じ日の Opus 4（142.65）と Sonnet 4（141.67）のように ECI が近いと、同時に開くと1発に見える。先頭が日付ちょうど、その後に「タ・タ・タン」と下の階層が続く連発にすれば、見ても聞いても数が分かる。
- `makeTimeline` の `onsets` にこのずれを入れ、描画・音・吹き出し・一覧・打ち上げペースはすべて `onsets` を使う。別の社の同じ日の発表は、従来どおり同時に開く。
- methodology の「バーストと音は日付ちょうど」の記述は、「各発表の先頭は日付ちょうど。同じ発表の残りは16分音符ずつの連発」に改める。

## 5. 表示

### 吹き出し（callout）
- 1行＝1発表。名前は `joinNames`（新設）で連ねる: 先頭は正式名、2つめ以降は先頭と共通する語の並びを省く（`Claude Opus 4 · Sonnet 4`、`GPT-4.1 · mini · nano`、`GPT-5.6 Sol · Terra · Luna`、`o3 · o4-mini`、`Llama 4 Maverick · Scout`、`Gemini 3.6 Flash · 3.5 Flash-Lite`）。最低1語は残す。区切りは ` · `。
- 副題は名前と同じ順の ECI: `ECI 143 · 142`、ECI なしは `—`。全部なしは従来どおり `NOT YET SCORED`。
- 行が現れる時刻は発表の先頭の時刻。まとめの時間幅（0.3秒）・行数（3行）・あふれ表示は従来どおり、ただし数える単位は発表。

### 右の一覧（ledger）
- 1行＝1発表。名前は `joinNames` を compact 表示（`Opus 4 · Sonnet 4`）。右端の数は先頭モデルの ECI。
- 「各行が4行以内に1.4秒以上残る」テストは発表の単位で維持する。
- 全モデル名が最小サイズで省略記号なしに収まることを、実データの全発表で確かめる。収まらない発表があれば、その列だけ名前の行を2行にするか、行の高さ・文字の最小サイズを調整して収める。`+N` での省略は使わない（名前が出ないことが今回の不具合なので）。

### 数の表示
- 見出し・カウンタ・字幕・統計表・まとめの「LAUNCHES」は、数えるものを花火の数（モデル）にそろえる: `N SELECTED MODELS`、`MAR · 12 MODELS`、統計表は `Models`・`Days / model`。
- 打ち上げペースもモデル単位で数える（1発ごとに約6.1を足す）。単位の表記を `MODELS / YEAR` にする。目盛り（60・30・14・7日に1回）は維持し、ピークが 1/WEEK の線を大きく超えるなら 3日に1回（約122）の線を足す。
- 一覧の下の基線のマーク、step line、マーカーは1モデルごと（同じ位置に重なってよい）。

## 6. 音

- 1発ごとに従来の打ち上げ音（上昇音・破裂・社の音色・パチパチ）を鳴らす。連発は16分音符の間隔なので、曲のリズムに乗る。
- 0.35秒以内の発で音量を `1/sqrt(n)` で分け合う仕組みは維持する。
- 受け入れの音の基準（各発で SFX ≥ BGM、500 Hz〜10 kHz）は全モデルで満たすこと。満たさない発があれば、その原因（連発の後ろの発が前の発の残響に埋もれる、など）を直す。

## 9. 検収記録

### 9.1 第1段（2026-10-20、GPT-6.1 Sol xhigh が実装、Claude が検収）

- 結果: schemaVersion 3、90モデル・79発表（ECI あり80）。`npm test` 75件成功、`npm run validate` 成功、`npm run qa:visual` 両形式成功（最大平均輝度 0.1235／0.1111）、`scripts/analyze-audio.mjs` で90発すべて SFX ≥ BGM（500 Hz〜10 kHz、破裂後80 ms、最小 +5.63 dB）。preview は旧データのままなので `verify:artifacts`・`verify:media -- --out preview` は第2段まで不一致で失敗する（想定どおり）。
- 設計どおり: 同じ発表の先頭は日付ちょうど、以降 `BAR_SECONDS / 16` ずつ遅れる。発表は保存せず `launchGroups` で導く。吹き出しは発表ごとに全モデル名と全 ECI を出し、近い発表のあふれ（3行まで）は発表の数で数える。
- 直したもの（第2段に依頼）: 一覧の compact 用の上書きで、縦長の名前が 32px → 22px に縮み、日付が次の行の名前の真上に来ていた（横長で次の名前まで約4px、自分の名前まで約20px）。1行に収まる名前は元の大きさに戻し、収まらない結合名だけ「 · 」で2行に折り、行の高さを行ごとに変える方式にする。吹き出しの印の白抜きは全モデルが preview のときだけにする。
- Claude が直したもの: DeepSeek の分割で ID が `deepseek-deepseek-v4-pro` と二重になっていた（依頼文の `<lab>-<名前>` の指定が原因）。既存の `deepseek-v3` などに合わせて `deepseek-v4-pro`・`deepseek-v4-flash`・`deepseek-v4-pro-0813` にした。
- 実行環境は Node 26.12.0。Node 22 での確認は CI に任せる。

### 9.2 第2段（2026-10-20、GPT-6.1 Sol xhigh が実装、Claude が検収・修正）

- データ: 7.2 の26モデルを追加して116モデル・96発表（ECI あり100、未採点16）。日付・名前・stage・出典 URL・ECI の行名が 7.2 と一致することを Claude が全件照合した。スコアは手元の CSV から `npm run scores` で入れた。要確認の3点（PaLM 2 の得点の対応、Claude Instant 1.2 と Epoch の `Claude Instant` の同定、Gemini 1.5 Flash の 05-10／05-14）は各 note と methodology に残した。
- 文言: README・methodology・reference の選定ルールを 2・7.3 に合わせた。件数・未採点一覧・年別の密度・終了時のペースは `scripts/sync-docs.mjs` が原本から書き、`verify:artifacts` が照合する。
- 一覧（ledger）: 1行に収まる名前は元の大きさ（縦長 32px、横長 28px）に戻り、長い結合名だけ「 · 」の後で2行になる。行の高さは行ごとに変わる。
